**Date:** 2026-04-10  
**Auditor:** Claude Code (automated codebase scan)  
**Scope:** All features listed on pricing pages vs. actual backend/frontend implementation  

---

## Context: Two Coexisting Pricing Models

⚠️ **The codebase contains two incompatible pricing systems running simultaneously:**

| | Old Model | New Model |
|---|---|---|
| **File** | `src/components/Pricing.jsx` (`/pricing` route) | `src/components/PricingPage.jsx` (`/app/pricing`) |
| **Plans** | Free ($0) / Pro ($18/mo) | Solo ($29) / Pro ($49) / Agency ($99) |
| **Trial** | None mentioned | 14-day free trial on all plans |
| **Backend** | `subscription_status = 'free' \| 'pro'` | `subscription_plan = 'solo' \| 'pro' \| 'agency'` |

The old `/pricing` page (`Pricing.jsx`) still exists as a public marketing page. The new `PricingPage.jsx` lives inside the authenticated app shell at `/app/pricing`. **All backend gating code reads `subscription_status == 'pro'` — it does not differentiate Solo vs. Pro vs. Agency.** The 3-tier system exists only in the billing/checkout flow, not in any feature-gating logic.

This audit covers **both** pricing pages.

## Plan Gating Audit

### What plan tiers exist in the data model?

**`subscription_status`** field (legacy, used for all feature gating):
- `free` — default for new users, 5 invoices/month
- `pro` — unlimited features (set by old billing webhook)
- `trialing` — 14-day trial via new billing system, grants Pro-level access
- `active` — active subscription via new billing system
- `past_due` — 3-day grace period
- `canceled` — access until period end
- `expired` — no access

**`subscription_plan`** field (new system):
- `solo` — set by `subscriptions/webhook.py` after Stripe checkout
- `pro` — set by billing webhook
- `agency` — set by billing webhook

### Does the app enforce plan restrictions?

**Invoice volume (free vs. paid):** ✅ YES — enforced in both `invoices/create.py` and `bedrock/conversation.py`

**Invoice color themes:** ✅ YES — backend rejects updates from non-Pro users; frontend hides UI

**Business name on PDF:** ✅ YES — gated in `pdf/generate.py` behind `is_pro`

**Stripe Connect access:** ⚠️ PARTIALLY — gated behind `subscription_status == 'pro'`, which may not be set for new Solo/Agency subscribers using the new billing flow

**Watermark removal:** ❌ NO — all users get the watermark regardless

**Reports/templates/team/portal/API:** ❌ NO — not implemented, so no gating to enforce

**Solo vs. Pro vs. Agency differentiation:** ❌ NO — no feature code distinguishes between `subscription_plan = 'solo'` and `subscription_plan = 'agency'`. All paid plans get identical feature access.

### Does a trial user get Pro access as promised?

**Partially.** `access_control.py` returns `plan: 'pro'` for trialing users. However, this module is **not wired into the actual feature checks** — invoice creation in `invoices/create.py` checks `subscription_status == 'pro'` directly, not the result of `get_user_access()`. A trialing user with `subscription_status = 'trialing'` would hit the free-tier 5-invoice limit.

### Are there features available to everyone regardless of plan?

Yes: AI invoice creation (modulo invoice count limit), PDF generation, client management, Stripe payment links on public `/pay` pages.
